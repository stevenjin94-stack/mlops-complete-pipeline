# Drift Monitoring Analysis

## Overview

This project uses Evidently to compare the training/reference dataset against simulated production data.

The production dataset is created from a random sample of the reference data and intentionally introduces several realistic distribution changes.

## Simulated Changes

Three features are intentionally modified:

### Age

Production values are shifted upward by approximately eight years.

This represents a possible change in the employee population over time, such as an increase in the average age of the workforce.

### MonthlyIncome

Production monthly income is increased by approximately 20%.

This could represent salary adjustments, inflation, changes in compensation policies, or a change in the employee population.

### OverTime

The production dataset sets the overtime category to "Yes" for all observations.

This represents a major operational change, such as a period of unusually high workload.

## Which Features Showed Drift?

The expected strongest drift is in:

- Age
- MonthlyIncome
- OverTime

The exact drift results are generated by Evidently and saved to:

`reports/drift_report.html`

Because the production dataset is intentionally simulated, the observed drift should be interpreted as a demonstration of monitoring rather than evidence of an actual business change.

## Would Drift Affect Model Performance?

Yes, it potentially could.

Employee attrition is influenced by factors such as compensation, overtime, and employee characteristics. A substantial change in these variables means that the production population may no longer resemble the population used to train the model.

For example, if overtime becomes substantially more common, the relationship between overtime and attrition could change the model's prediction distribution.

Similarly, a shift in monthly income could change the relationship between compensation and attrition.

Feature drift does not automatically mean model performance has degraded, but substantial drift should trigger further investigation.

## Recommended Action

The recommended action is:

**Investigate first, then retrain if production performance has degraded.**

The team should:

1. Verify that the drift is real rather than a data pipeline error.
2. Check whether the feature distributions changed because of a legitimate business event.
3. Compare production model performance against labeled outcomes when labels become available.
4. Retrain the model if the production relationship between features and attrition has materially changed.

If drift remains below the configured threshold and production performance remains stable, the team can continue monitoring.
